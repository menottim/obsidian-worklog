# DM Sweep for /worklog pull — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend `/worklog pull` to sweep the user's Slack 1:1 + group DMs since the last sweep, classify them against the worklog, and surface relevant items — with DM content never auto-folded (approval-only, genericized).

**Architecture:** A single `Sources/_dms.md` config (global `last_scan_ts`) drives an auto-enumerated DM sweep. A new `slack-list-dms` helper enumerates the user's DM conversations (the one capability MCP lacks); reading reuses the existing `slack_read_channel`/`slack_read_thread`. DM units run the existing three-way classifier but bypass auto-fold — every relevant item goes to the one-by-one approval batch and is folded only on approval as a genericized, workstream-level summary. Spec: `docs/superpowers/specs/2026-06-05-dm-sweep-design.md`.

**Tech Stack:** Markdown skill prose (`SKILL.md`), Claude Code plugin packaging (`plugin.json`, version-keyed cache), Slack Web API (`users.conversations`) via a ~30-line bash helper (`curl` + `jq`), Slack MCP (`slack_read_channel`/`slack_read_thread`), `evals/evals.json`, bash (`git`, `rsync`, `sed`).

Insert immediately after the `### Source type: \`context-channel\`` subsection (before `## Meetings`):

````markdown
### Source type: `dm-sweep`

A third source type that sweeps the user's Slack __direct messages and group DMs__
(MPIMs) — not a single channel. DMs are auto-enumerated, so there is __one__ config file
for the whole sweep, `Sources/_dms.md`:

```yaml
---
type: dm-sweep
enabled: true
include_1on1: true
include_groups: true
last_scan_ts: null              # global baseline; first run = now − first_scan_lookback_days
first_scan_lookback_days: 3
nudge_threshold_days: 5
exclude_users: []               # user IDs/names whose 1:1 DMs are never swept
exclude_conversations: []       # specific conversation IDs (im/mpim) to skip
---

# Direct Messages

Auto-enumerated DM + group-DM sweep. One global `last_scan_ts`, incremental by message
timestamp. DM content is __never auto-folded__ — everything routes through the approval
batch and is folded only on approval, as a genericized workstream-level summary.
```

Notes:
- A single global `last_scan_ts` governs the whole sweep (a message is new if
  `ts > last_scan_ts`); there is no per-conversation state.
- Enumerating the user's DMs needs the `slack-list-dms` helper (there is no MCP
  `conversations.list`). Reading each DM reuses the MCP (`slack_read_channel` /
  `slack_read_thread`).
- Requires one-time token scopes `im:read` + `mpim:read` (see `docs/SETUP-SLACK.md`).
````

- [ ] **Step 2: Add the DM-sweep flow to `/worklog pull`**

Insert after the `__Approval batch (human-in-the-loop)__` subsection and before
`__First-run registration:__`:

````markdown
__DM sweep flow:__

If `Sources/_dms.md` exists and is `enabled: true`, run this after all channel sources
(its candidates join the same end-of-pull approval batch):

1. Enumerate the user's DMs by running the helper (unconditionally; do not pre-check
   "is it configured" — run it and branch on exit code, same pattern as `slack-fetch-file`):
   ```bash
   ~/.config/obsidian-worklog/bin/slack-list-dms
   ```
   It prints one conversation per line: `<id><TAB><im|mpim><TAB><other-user-id-if-im>`.
   On any non-zero exit, print a one-line skip note with the helper's stderr and __skip the
   DM sweep__; the rest of the pull is unaffected.
2. Filter the list: drop entries whose id is in `exclude_conversations`; drop `im` entries
   whose other-user-id is in `exclude_users`; honor `include_1on1` / `include_groups`.
3. Window: messages with `ts > last_scan_ts`. First run (`last_scan_ts` null): look back
   `first_scan_lookback_days` (default 3).
4. For each conversation, `slack_read_channel` since the window (bots excluded); expand
   group-DM threads via `slack_read_thread` as needed. Build conversation units (a unit is
   a thread or a standalone message).
5. __Volume guardrail:__ if total DM units exceed ~100, STOP and ask (proceed / narrow /
   skip). Never silently truncate.
6. Classify each unit against the __entire vault__ using the three-way rubric above, with
   the DM privacy override below.
7. Advance `last_scan_ts` to the current time after the sweep completes.

__DM privacy override (differs from channels):__
- __DM content is never auto-folded.__ Every relevant DM unit — high-confidence match
  included — goes into the approval batch. High-confidence ones lead with the recommended
  "attach as a sub-item under `[[matched item]]`" option; weak/new ones offer attach / new
  `P?` item / Backlog / drop (new standalone items are allowed). Noise is dropped silently.
- On approval, fold a __genericized, workstream-level summary__ — no verbatim 1:1 quotes,
  no personal detail beyond what the item needs (honors the user's "no DM quotes in public
  artifacts" rule even though the vault is private). Provenance: a Slack permalink to the DM
  message. Dated with the Slack timestamp; wiki-linked; frontmatter regenerated only if a
  top-level item is added.
````

**Files:**

- [ ] **Step 1: Add a "DM sweep setup" section**

Append this section to `docs/SETUP-SLACK.md`:

````markdown
## Optional: DM sweep setup

To let `/worklog pull` also sweep your 1:1 + group DMs, do two one-time things.

### 1. Add scopes to your Slack user token

The DM sweep enumerates your conversations via Slack `users.conversations`, which needs
`im:read` + `mpim:read` in addition to the existing `files:read`. In your Slack app at
`api.slack.com/apps` → OAuth & Permissions → User Token Scopes, add `im:read` and
`mpim:read`, then reinstall the app to your workspace and update the `xoxp-` token at
`~/.config/obsidian-worklog/slack-token` (chmod 600). (Reading the DMs themselves uses the
Slack MCP, which already has access — only enumeration needs these scopes.)

### 2. Install the `slack-list-dms` helper

Save this as `~/.config/obsidian-worklog/bin/slack-list-dms` and `chmod +x` it:

```bash
#!/usr/bin/env bash
# slack-list-dms — list the calling user's DM + group-DM conversations.
# Output (one per line):  <conversation_id>\t<im|mpim>\t<other-user-id-if-im>
# Exit 0 on success; non-zero with a one-line stderr message on any failure.
set -euo pipefail

TOKEN_FILE="${SLACK_TOKEN_FILE:-$HOME/.config/obsidian-worklog/slack-token}"
[[ -r "$TOKEN_FILE" ]] || { echo "slack-list-dms: token file not readable at $TOKEN_FILE" >&2; exit 3; }
TOKEN="$(tr -d '[:space:]' < "$TOKEN_FILE")"
[[ -n "$TOKEN" ]] || { echo "slack-list-dms: empty token" >&2; exit 3; }

cursor=""
while :; do
  resp="$(curl -sS -G "https://slack.com/api/users.conversations" \
    -H "Authorization: Bearer $TOKEN" \
    --data-urlencode "types=im,mpim" \
    --data-urlencode "exclude_archived=true" \
    --data-urlencode "limit=200" \
    ${cursor:+--data-urlencode "cursor=$cursor"})" \
    || { echo "slack-list-dms: network error calling users.conversations" >&2; exit 4; }

  if [[ "$(printf '%s' "$resp" | jq -r '.ok')" != "true" ]]; then
    echo "slack-list-dms: slack api error: $(printf '%s' "$resp" | jq -r '.error // "unknown_error"')" >&2
    exit 5
  fi

  printf '%s' "$resp" | jq -r '.channels[] | [.id, (if .is_im then "im" else "mpim" end), (.user // "")] | @tsv'

  cursor="$(printf '%s' "$resp" | jq -r '.response_metadata.next_cursor // ""')"
  [[ -n "$cursor" ]] || break
done
```

Test it: `~/.config/obsidian-worklog/bin/slack-list-dms | head` should print conversation
IDs. A non-zero exit (missing scope, bad token) makes `/worklog pull` skip the DM sweep
gracefully.
````
